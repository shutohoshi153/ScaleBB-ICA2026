# How to Propose Changes (Co-authors and Reviewers)

*English translation of [CONTRIBUTING.md](CONTRIBUTING.md) (as of 2026-08-05). If the versions disagree, the Japanese version is authoritative.*

This repository is synchronized bidirectionally with the author's working repository.
**Co-authors are welcome to commit and push directly to `main`.** The author reviews
the content when incorporating it into the working repository.

## How to make changes

### Direct commits (co-authors)

```bash
git pull            # <- always run this first
# edit
git commit -am "Align the symbol definitions in §3.2 with SOA (2012)"
git push
```

**Always run `git pull` before pushing.** If you miss content the author has synced,
the histories diverge from that point on and resolving them takes extra work.

If the commit message states in one line which section was changed and how,
it speeds up the author's review.

### Comments and consultations (reviewers, and whenever discussion is wanted)

For comments where a concrete fix has not yet crystallized, or for consultations
on direction, please open an Issue. It helps if you identify the location by file
name and section number, e.g. §3.1.2 of `sections/03_data_and_methodology.md`.

For large structural changes (adding or removing sections, changing the chapter
structure), please raise it briefly in an Issue before committing directly.

## How synchronization works (just enough to be reassuring)

The contents of `main` correspond one-to-one with the manuscript directory in the
author's working repository. The author synchronizes in two directions:

- **Public → working repository**: co-authors' commits are pulled in as diffs, reviewed, and committed
- **Working repository → public**: the author's additions are reflected to `main`

While `main` contains changes that have not yet been incorporated, the author-side
sync tool stops automatically. Co-authors' commits therefore cannot be rolled back
unnoticed.

Note that `LICENSE` is managed only on the public repository side and is excluded
from synchronization.

## About the reproduction packages

The two packages under `reproduction/` can be run standalone. See each `README.md`
for the procedure and the expected figures. If the figures do not match, please open
an Issue including your execution environment (Python and the versions of the main
libraries).

`reproduction/backtest/output/`, generated by the reproduction runs, is untracked.
There is no need to commit generated artifacts.

## Data handling

The bundled data includes third-party statistics. When reusing them, follow the
citations and terms of use in [`DATA_SOURCES.md`](DATA_SOURCES.md).
The repository's `LICENSE` (text CC BY 4.0 / code MIT) does not extend to these data.
